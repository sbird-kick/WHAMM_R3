3. BAKED TEST VECTORS  (embedded in db_zlib_decompress_05.c / db_zlib_rawdeflate_06.c)

  by a NATIVE (host cc) miniz build, then pasted into the .c files:

    05  VEC[267] = mz_compress( 256-byte LCG buffer, seed 0x1234567 )  -> zlib stream
                   raw adler=dac18015 crc=5b236695

                   TDEFL_DEFAULT_MAX_PROBES )                          -> raw deflate

  Regenerate (host):
    cc -I $DB_SRC/miniz-3.0.2 -DMINIZ_NO_STDIO -DMINIZ_NO_TIME -DMINIZ_NO_ARCHIVE_APIS \
       <generator>.c $DB_SRC/miniz-3.0.2/miniz.c -o gen && ./gen

4. SQLITE — CLASSIFIED FAILING (whamm bug), see gen_candidates/failing/
-----------------------------------------------------------------------
  Build recipe (also in db_build.sh, sqlite_build()):
    clang -Oz -DSQLITE_THREADSAFE=0 -DSQLITE_OMIT_LOAD_EXTENSION -DSQLITE_DEFAULT_MEMSTATUS=0 \
      -DSQLITE_DQS=0 -DSQLITE_TEMP_STORE=3 -DSQLITE_OMIT_DEPRECATED \
      -ffunction-sections -fdata-sections -Wl,--gc-sections -I <sqlite> \
      db_sqlite_basic_01.c <sqlite>/sqlite3.c -o db_sqlite_basic_01.wasm
  The .wasm runs & is deterministic under wizeng (count=20 sum=118 max=12), but
  `whamm instr` STACK-OVERFLOWS on it (2332 fns); see the .note.txt.
  NOTE: do NOT add -DSQLITE_OMIT_AUTOINIT — it skips default-VFS registration and
  makes sqlite3_open() call a null VFS pointer -> FUNC_INVALID trap.
